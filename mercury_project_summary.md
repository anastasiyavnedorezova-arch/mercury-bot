## 3. Инфраструктура и выкладка

- **Сервер Timeweb Cloud, Новосибирск, 129.101.119.154**: прод `/opt/finnik/app` (сервис `finnik`, база `finnik`), stage `/opt/finnik-stage/app` (сервис `finnik-stage`, база `finnik_stage`, только системные категории).
- **Ретранслятор в Нидерландах** (Hostkey, `relay.finnikbot.ru`): Telegram и OpenAI недоступны с российского IP, поэтому идут через него. Тела запросов нигде не сохраняются. Описание, что делать при падении, и runbook «новый ретранслятор за 15 минут» — `deploy/relay/README.md`.
- **DNS** — Cloudflare. **Репозиторий** — GitHub `anastasiyavnedorezova-arch/mercury-bot` (приватный), локально `~/Documents/mercury-bot`.
- **Порядок выкладки**: патч → Claude Code применяет на ветке `staging`, `npm test`, коммит, пуш, `finnik-stage-deploy.sh` → Анастасия проверяет на stage → её «ок на прод» → `git merge --ff-only staging` в `main`, `finnik-deploy.sh` (автоматический бэкап базы перед выкладкой). Миграции базы применяются вручную к `finnik_stage` и `finnik` **до** выкладки кода, который их использует. Откат: `git revert` + обычная выкладка.
- **Копии базы**: `finnik-backup.sh` каждую ночь (cron 00:30 UTC) и перед каждой выкладкой, в `/root/backups` (3 дня) и в S3 Timeweb `finnik-backups/daily` (30 дней). Пробное восстановление и репетиция полного восстановления проведены 20.10. Временные таблицы в базе называть `tmp_*` (бэкап их пропускает) и удалять сразу после проверки.
- **Мониторинг**: `finnik-health` раз в 5 минут, 8 проверок (приложение, база, Telegram, OpenAI, свежесть бэкапа до 26 ч, диск, сертификаты, расход ИИ); алерты письмом и в отдельный Telegram-бот; на ретрансляторе свой сторож `finnik-watch`; UptimeRobot проверяет только открытие сайта.
- **Просмотр базы**: DBeaver на Mac через SSH-туннель, пользователь только для чтения `finnik_ro`.

## 6. Бот

- **Онбординг (патчи 56–57)**: приветствие «Привет! Я бот сервиса Финник Деньги», согласие, «Я дарю тебе 30 дней…», главная кнопка «✍️ Записать первую трату», «Что ещё умею»; после самой первой записи один раз подсказка про цель и бюджет; через 3–24 ч без записи один раз напоминание (9:00–21:00 МСК).
- **Меню**: «Записать расход или доход» (на всю ширину), «История транзакций» + «Мои категории», «Моя цель» + «Мой бюджет», «Аналитика» + «Управление подпиской», «Личный кабинет» (ссылка на `/cabinet/login`; в веб-чате скрыта), «Обратная связь» + «Задать вопрос».
- **Распознавание записи**: сначала быстрый разбор «слова + одна сумма» без ИИ (`quickParse` + справочник `categoryHints`: категории, магазины, организации, сокращения), потом личная память фраз человека (`phraseMemory`), потом ИИ; неизвестное слово с суммой идёт в «Остальное» с кнопкой «Исправить»; «обучение бота» — вопрос «передать фразу разработчикам?» и сигнал админу в Telegram.
- **Цели**: взносы привязаны к цели (`goal_id`), прогресс = стартовая сумма + взносы; при нескольких целях бот спрашивает, на какую.
- **Бюджет**: считает все расходы месяца, включая Жильё, Кредиты и займы и Цель; в прогнозе эти крупные траты не растягиваются на остаток месяца, бот об этом пишет (`budgetCalc.js`).
- **Лимиты ИИ**: 50 запросов на человека в сутки (по МСК), общий лимит 3000; вес: текст и вопрос 1, голос 2, выписка 5.
- **Уведомления** (ежедневно в 10:00 МСК, только Telegram-аккаунты с принятыми условиями и активностью за 30 дней): напоминания про бюджет (1, 3, 5 числа), вносить записи (после 3 дней без записей, не больше 4 за 30 дней), алерты бюджета 50% / 80% / прогноз, окончание пробного периода и подписки, итоги месяца 1 числа.
- Команда `/stats` (только админ): воронка регистрация → первая запись → оплата, платежи, источники.

## 14. Как работать с Claude Code и со мной

- Один шаг за раз; на каждый патч: файл `.patch`, промпт для Claude Code (всегда «ветка staging»), чек-лист проверки (сначала кабинет, потом Telegram). На прод ничего не выкатывается без явного «ок на прод».
- Тексты для пользователей: на «ты», без «вы» и форм на -ите/-ете (проверяют тесты).
- Секреты и токены в чат не вставлять.
- Тесты: `npm test` (в cloud-контейнере полный прогон около 10 минут). Новый тестовый файл добавлять в список в `package.json`.
- Устаревшая версия этого саммари лежит ещё и в корне репозитория (`mercury_project_summary.md`): её стоит заменить этой версией или удалить (в ней старые ссылки на Supabase и платёжные ссылки).

*Обновлять этот файл после каждой значимой сессии (после выкладки на прод).*
